# Release note, field-pass speed-ups (for the second-order release)

- The field passes of `qtf_terms = full` and `qtf_b2 = control` are faster: on the OC4 WAMIT model (5022 panels, sum QTF) the run takes 2.08 h (49.8 core-h) instead of 7.25 h (174.1 core-h), 3.5 times faster, and is 2.6 times faster than Nemoh v3.0.3 on the same mesh (5.46 h). The changes are deep-water Green-function rows at finite depth from k0 h = 10 on the free surface (z = 0), reuse of ψ in the fields passes, a threaded mode check, and the partial waves on the circle from the hull integral. That OC4 run also used deep-water rows on the control surface C and F. These are now finite-depth rows again (see below), so the C/F part of the time will rise; the OC4 timing with this fix is not measured yet.
- On by default: `field_deep_kh = 10` and `qtf_fs_circle = panels`. Switch them off with `field_deep_kh = 0` (gives the earlier results to the byte, apart from `qtf_fs_circle`) and `qtf_fs_circle = samples`. The ψ reuse and the threaded check have no key and give the same bits as before. `qtf_fs_inner = source` is off by default (`stencil`) because it failed the accuracy gate; do not switch it on for results.
- The deep-water rows apply to the free-surface rows (z = 0) only. Below z = 0 they miss the seabed images of the finite-depth Green function: at control-surface bottom points they are 2.3e-3 to 9.3e-3 of the row maximum off on an OC4-like case and 0.15 to 0.19 off with 1 m of bottom clearance, while the finite-depth rows are within 7e-5 (unit test `field_row_deep_seabed`). The C/F passes therefore keep the finite-depth rows.
- On OC4, the run with the new defaults (deep-water rows on C and F as well) moved `QTF_Indirect.11s` by up to 6.6 % of the largest value below 1.55 rad/s and by more above 1.6 rad/s (35.1 % for mode 6, 62.5 % for the B2 term). A re-run with the control-surface passes on finite-depth rows is pending; until then the cause of the OC4 change is open. Against WAMIT the quadratic and body part moves closer (maximum F_x error 13.7 to 10.0 %) and the HAMS total slightly away (maximum F_x 103.0 to 104.4 %); the total is dominated by the free-surface part, so it does not decide the question.
- Details: `docs/second_order_validation.md` (Field-pass speed-ups) and `docs/input_files.md` (`field_deep_kh`, `qtf_fs_circle`, `qtf_fs_inner`).
