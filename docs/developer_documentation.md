## Tests

HAMS-MREL includes both unit tests and integration tests written using the [Test-Drive](https://github.com/fortran-lang/test-drive) framework. The tests are designed to ensure that both individual components (subroutines, functions) and full simulation workflows are correct.

The tests are defined in [fpm.toml](../fpm.toml) as two separate executables: unit-tester and integration-tester. The unit-tester runs small-scale tests on individual subroutines and functions. The integration-tester runs full simulations for pre-defined test configurations and compares outputs with reference results. All of the data needed for the tests in included in the tests/data folder.

### Running the tests

HAMS-MREL can be built using multiple methods, but tests must always be run via **fpm** because they rely on the fpm build/test environment configured in `fpm.toml`. fpm will automatically install and link the Test-Drive framework to the test executables.

```bash
# FPM: set the compiler to IFX
export FPM_FC=IFX

# FPM: set the compiler flags
# `-heap-arrays 0` is required to keep large multi-body cases from overflowing the per-thread
# stack — see the installation docs for the full explanation.
export FPM_FFLAGS="-qmkl -qopenmp -heap-arrays 0"
export FPM_LDFLAGS="-qmkl -qopenmp"

# Compilation step. Build is handled by FPM (HAMS-MREL and test executables will be placed in build directory)
fpm build

# Place the executable in 'install' directory (an exact locaion is needed by integration tests)
fpm install --prefix install

# Run unit tests
fpm test --target unit-tester

# Run integration tests (they expect the path to the executable as an argument)
fpm test --target integration-tester -- install/bin/hamsmrel
```

The integration tests compare against the outputs stored in `test/data/config1/expected_output` with a relative tolerance, because results change slightly between compilers and flags. The measured differences behind each limit are listed in [test_integration.f90](../test/test_integration.f90). Regenerate the stored outputs only when a change is meant to alter the results.

### Free-surface image term

The Green function holds the image term 1/r1 of the free surface. Until this change it was taken at the centroid of the source panel and multiplied by the area, also for panels next to the field point, while the 1/r term was integrated over the panel. On a panel close to z = 0 compared with its size, the centroid is too close to its image: for the top row of a wall graded to the waterline, with height 0.02 m and width 0.65 m, the one-point value is 4.7 times the integral. Now, for every pair within 50 panel sizes (`FLAG = 1`), `IMAGE_TERM_EXACT` and `IMAGE_TERM_EXACT_MULTI` move the term and its gradient out of the Green function and add their integral over the panel. They are called in `CALGREEN`, `CALGREEN_IRR`, `CALGREEN_MULTI`, `CALGREEN_MULTI_IRR`, `CalPotential` and `CalPotentialMulti`, so collocation and field points are treated the same. This changes first-order results on all meshes, a little: see [the fixtures](../test/data/image_term/README.md). The stored outputs of `config1` were regenerated for it.

One-point and integrated image terms converge to the same limit at second order. On half-spheroids in deep water, from 144 to 9216 panels, with even and thin top rows, A and B from both agree with the exact limits to within 0.13% at the finest mesh, and neither is the more accurate in every mode. The integrated term makes the results depend less on the lid: at 576 panels the median change from adding one is 0.03 percentage points, against 0.08 with the one-point term.

The rest of the Green function stays at the centroid: the logarithmic part of the wave term, also singular at the free surface; in deep water the term `2V/R1` of `GRN(4)`, the z gradient of the wave part (`InfGreen_Appr.f90`), which is stronger near z = 0 than the logarithm; and with finite depth the image in the sea bed.

A hull panel with its centroid on z = 0 has no usable image term: the distance from the centroid to its own image is zero. `CalNormals` and `CalNormalsMulti` stop with a message on such a mesh. Before this check, the same mesh ran to the end and wrote NaN.

### Triangle panels

The triangle routines (`SGLINTBD_TRI`, `SGLINTBD_TRI2` and their multi-body copies) work from `ALFA`, the projection of side 1-3 on side 1-2, in units of side 1-2. Until this change they integrated over the wrong shape when `ALFA > 1`, an obtuse angle at node 2, so the result depended on the node order. This affected the direct term 1/r as well as the image term, in every earlier version. Results now change on any mesh with such a triangle as a hull panel. Lid panels are never sources, so their node order does not matter. Quadrilaterals were not affected. See [test_panel_integrals.f90](../test/test_panel_integrals.f90).

Before the merge, with the potential part alone, they were 226 and 169 (see [QTF potential part](#qtf-potential-part)). With the quadratic QTFs (Phase 4), the unit tester had 185 tests and the integration tester 147, all passing with ifort 2022.1 on Windows. With the control-surface method, before them, it was 177 and 141. At commit dff7a32, before the control-surface method, they had 133 and 118, all passing with ifort 2022.1 on Windows and with ifx 2024.2 on Linux; the times below are from then. Measured run time: the integration tests take 148 s with ifort on a laptop with 8 logical cores and 177 s with ifx at 32 threads on Snellius; the unit tests take 19 s with ifx. All cases stay in CI. The time on the GitHub runners is not measured here; GitHub's default job limit is 6 hours.

`QTFDriver.f90` keeps, for the QTFs, the converted state of every frequency and heading: φ_I, φ_P, ∇φ_I, ∇φ_P (8 complex values per panel, 128 bytes) and the motions, and the waterline potential. The whole store is allocated by `qtf_init` at set-up, so a run that does not fit stops before the first-order solves. `qtf_keep` must be called for every heading of a frequency, in order (heading 1 starts a new frequency), and only for the frequencies of the QTF grid, which leaves out the limits of `SYBO = 1`; it stops if it is called out of order. Its state is module state, so the unit tester runs the `qtf` suite serially.

### QTF potential part

The body forcing of the second-order potential in the difference QTF (`qtf_terms = body`, Phase 5). Usage is in [QTFs, potential part](input_files.md#qtfs-potential-part), the files in [Output Files](output_files.md#wamit-format), and the validation in [Second-order validation](second_order_validation.md#qtf-potential-part).

**Formulation.** Time factor e^{−iωt}, normals out of the fluid, per unit wave amplitudes. At Ω = ω_1 − ω_2, with the free-surface integral left out,

T_pot,k = iΩρ [ ∬_S φ_I2 n_k dS + ∬_S ψ_k (B − ∂φ_I2/∂n) dS ],
B = (Ẋ − u)·(α × n) [B1] − n·[(X·∇)u] [B2] + n·d/dt(H x) [B3], H x = ½ α × (α × x),

with X = ξ + α × (x − x_r) the first-order motion, u the total first-order velocity and ψ_k the radiation potential of mode k at Ω (∂ψ_k/∂n = n_k). This is the indirect (Haskind) method of Molin (1979) with the second-order body condition on the mean surface of Ogilvie (1983); see also WAMIT v7.5 (ch. 15) and Chen (1988). Moments come from ψ_4 to ψ_6, so no moment arm enters. Every product of two first-order quantities uses the difference kernel of `NearFieldDrift` (`pair_product`, `pair_cross`), as the quadratic part does. For Ω < 0, ψ(−|Ω|) = ψ(|Ω|)* is used, so T_pot(2, 1) = T_pot(1, 2)*.

**B2.** The direct integrand n·[(X·∇)u] is not integrable at a sharp edge, where u ~ ρ^(−1/3). Stokes' theorem on S, bounded by the waterline Γ, gives

∬_S ψ n·[(X·∇)u] dS = R + S_B2 + L, R = ∬_S ψ n·(α × u) dS, S_B2 = ∬_S (n × ∇ψ)·(X × u) dS, L = −∮_Γ ψ (X × u)·t dl,

so B2 = −(R + S_B2 + L), and only first derivatives of φ and the tangential gradient of ψ enter ([QTFPotential.f90](../src/QTFPotential.f90)). S_B2 has a ρ^(−2/3) integrand at the edge and converges slowly with one point per panel. With `qtf_b2 = control` it is moved off the hull. For a rigid field A and harmonic φ, ψ (v = ∇φ), the tensor T_ab = v_a ∂_bψ + v_b ∂_aψ − δ_ab (v·∇ψ) is divergence-free and div(T A) = 0; this extends the Gauss identity of Chen (2007, App. C, eq. 63 to 65) to two potentials, as Cong et al. (2020, eq. 35 to 39) use it for the second-order body condition. On the fluid between the hull S, a closed control surface C (wall and bottom) and the free surface F between the waterline and C:

S_B2 = H + CF_T, H = ∬_S ψ_n (A·v) dS, CF_T = ∬_{C∪F} [ (A·v) ψ_no + (A·∇ψ) v_no − (A·n_o)(v·∇ψ) ] dS,

with n_o out of the control volume on C and F (the opposite of `cs_points%nrm`). No line integral enters. H needs no ∇ψ and is singular like u only; ∇ψ on C and F is smooth. R and L stay on the hull. One rigid A per control volume, so each C must enclose its own body only, and must have a bottom: a C that reaches the sea bed would leave the sea bed as a boundary of the volume, whose term is not implemented. Moving L to C ∪ F as well, and R, was tried on the exact reference and not kept ([validation](second_order_validation.md#tried-and-not-kept)).

**Fields on C and F.** `fields_green` needs the solver globals at the state's frequency. So the total velocity on C and F is evaluated at the end of each kept frequency (`so_end_frequency`, once for the control-surface drift and B2), and ∇ψ_k when ψ is taken at each Ω (`keep_cs_psi`, one pseudo-state per mode with no incident wave and ∂ψ_k/∂n = n_k on its body). Both go to the QTF store.

**Threads.** `fields_green` ([FieldVelocity.f90](../src/FieldVelocity.f90)) runs its loop over the points in parallel: each point writes only its own values, with no reduction, so the result does not depend on the thread count (unit test `green_field_thread_invariant` in `test/test_field_velocity.f90`). The panel loop of `field_influence_row` inside it is also an OpenMP loop and runs serially there while nested parallelism is off, the default. With nested parallelism on, the threads multiply (up to `NTHREAD`²); nothing guards against that. Measured on the 448-panel fixture with 686 points on C and F, one pass: about 150 s on 1 thread, 45 s on 4 threads (55 s before the point loop was threaded) and 28 s on 8; the outputs did not change.

**Notes for development.**

- HAMS's panel centroids are vertex averages. On strongly trapezoidal panels they leave a large O(h²) constant in a nearly cancelling closed-surface integral: on a sphere of 2048 panels, the Stokes form of the B2 integral differed from the direct form by 1.9e-2 (relative) with vertex-average centroids, against 5.5e-4 with area centroids (`test/test_qtf_potential.f90`). The unit test uses area centroids. Whether the vertex-average centroids of the cylinder meshes' bottom rings add a constant of this kind to their results was not measured.
- u at the waterline: the line term L with u extrapolated along a differenced panel is only O(h). `waterline_velocity` builds u at each waterline segment from the incident wave (exact), the free-surface condition (u_z), the body condition (normal part) and differencing of φ along the waterline (tangential part); B2 is then O(h²) (5.42e-3, 1.48e-3, 3.87e-4, ratios 3.66 and 3.83, `test_qtf_potential.f90`). This was measured on a regular cylinder only; an irregular spacing of the waterline segments was not measured.
- The tangential differencing of φ along the waterline runs across sharp waterline corners, which makes it O(h) next to the corners of a box barge [derived, not measured]. Flared (sloped) waterline panels are not covered by a test.
- The diagonal test is exact equality of the two frequencies, so the callers pass the same grid value for both states.
- The unit tests pin the signs of the terms as specified; the physical signs are checked only against the exact reference (`truncated_cylinder_reference.py qtf-potential`), whose signs are derived from the boundary-value problem.
- After a change to the layout of a type in `SecondOrderTypes` (such as `surface_geom`), delete the stale objects of fpm's build before testing.

### QTF free-surface terms in the driver (qtf_terms = full)

With `qtf_terms = full`, `potential_part` ([QTFDriver.f90](../src/QTFDriver.f90)) adds two terms to the five of `potential_pair`: FS_inner and FS_outer, from `fs_pair_terms` ([QTFFreeSurface.f90](../src/QTFFreeSurface.f90)). For each pair of stored states:

- FS_inner is `fs_inner_pair`, the panel sum over the inner free-surface mesh. FS_outer is `fs_outer_pair` from R to `fs_outer_rfar` and its tail, plus `fs_outer_sliver` over the gap between the polygon of a generated inner mesh and the circle. A mesh from `FSInnerMesh.pnl` has no sliver; `fs_coverage_check` checks that it covers the free surface inside R to 1% (warning) and 10% (stop).
- **Omega = 0** (the diagonal) has no free-surface term. `fs_pair_terms` returns zeros before any outer routine is called, since those need Omega > 0.
- **Pair order.** The outer routines need ω₁ > ω₂. A pair with ω₁ < ω₂ is computed as the pair (2, 1) at −Ω > 0, with the same stored ψ, and conjugated. In the internal e^{−iωt} convention this gives T(1, 2) = conj T(2, 1) [derived]. Under KERNEL_DIFF, Q_D(2, 1) = conj Q_D(1, 2) (pair_product). Also ψ(−Ω) = conj ψ(Ω) and i(−Ω) = conj(iΩ). `potential_pair` uses the same identity for the hull terms. Tests: `fs_inner_pair_hermitian`, `fs_pair_terms_order`, and `qtf_body_hermitian` on the full fixtures.
- **Gravity.** The free-surface terms take `s%g`, the gravity G of `Const_mod`. This is the g of the solver's free-surface condition and of the ψ solve. The hull Froude-Krylov term of φ_I2 takes `wave_gravity` (g_wave, ruling R8 of Phase 5), as do the incident fields at the inner points (`incident_at`). The two differ by about 0.004% (DISPERSION's g = 9.807 against 9.80665) [derived]. This is a convention, not an error of the method.
- **Tests.** With the free-surface integral the unit tester has 293 tests and 1 expected failure, and the integration tester 190, all passing with ifort 2022.1 on Windows (2026-11-13). The unit tests are in `test/test_qtf_free_surface.f90`, `test/test_partial_waves.f90` and `test/test_control_surface_mesh.f90`; the integration cases `qtf_fs_*` in `test/test_integration_drift.f90`.
- The pairs run one after another. Only the radial annulus of the outer integral is parallel. Each radial interval keeps its own sum, and the sums are added in order, so the annulus has the same bits for any number of threads (`fs_outer_annulus_threads`). `pw_decompose` calls MKL `DGELS`, whose bits across MKL thread counts were not tested.
- **Cost at small Ω.** r_far − R is at least 20 periods of the slowest phase class, 2π/(k₁ − k₂ + K), which grows like g/(2ωΩ) as Ω → 0 (about 1e5 m at ω = 0.5, Ω = 0.01 rad/s): many radial intervals per pair in the serial pair loop. The log gives r_far per Ω.
- **Circle R and the hull.** R must exceed the waterline radius and the hull radius (`hull_radius`, the largest horizontal distance of a hull node from the centre), else the run stops: on a hull wider below the waterline the partial waves would be sampled inside the body. The automatic R and N_ev use the larger of the two radii.
- **Inner mesh.** `build_fs_inner` (ControlSurfaceMesh.f90) builds strips from the waterline to a polygon of ceil(2πR/ps) chords on the circle, ps = λ/10 at the largest frequency or `qtf_fs_panel`; the rows are the fewest, at least 2, whose outer row is not thicker than ps, graded by 4 towards the waterline; the columns are the hull waterline nodes plus the polygon vertices (`strip_columns` with `follow`), so the mesh refines with the hull. Automatic R = r_wl + max(0.5 r_wl, 2 × the largest hull panel).
- **Accuracy and the default.** Validated on the sharp cylinder against the exact reference ([validation](second_order_validation.md#qtf-free-surface-integral)): the default converges with the hull mesh (free body 12 / 4.5 / 2.2% in F_x at m1 / m2 / m3) and was kept (user decision, 2026-11-13). At m1 the error is not monotone in the inner mesh (more rows alone worse; λ/30 worse than λ/20); the cause is not found. The first ring of points lies within one hull panel of the hull there, where the constant-panel first-order field and the shrunken Laplacian stencil are least accurate; a comparison of those fields with the exact first-order field at the inner points would settle it. The log notes the mesh on every run with the generated mesh.

### Direct method (QTFDirect.f90)

The direct solution of the difference-frequency second-order potential with body forcing (`qtf_direct = 1`, Phase 7a) and, with `qtf_terms = full`, with the free-surface forcing (Phase 7b, [below](#free-surface-forcing-of-the-direct-solve-phase-7b)). The sum frequency (Phase 7c-2) is [further below](#sum-frequency-of-the-direct-method-phase-7c-2). Usage is in [QTFs, potential part](input_files.md#qtfs-potential-part), the file in [Output Files](output_files.md#wamit-format), and the validation in [Second-order validation](second_order_validation.md#direct-method-against-indirect-method).

**Formulation.** At Ω = ω_1 − ω_2, φ_D solves Laplace's equation with the bottom and radiation conditions, −Ω²φ_D + g ∂φ_D/∂z = Q_D on z = 0 (Q_D = 0 with `qtf_terms = body`, the case of 7a; the forcing of `full` is [below](#free-surface-forcing-of-the-direct-solve-phase-7b)), and ∂φ_D/∂n = b on S with b = B − ∂φ_I2/∂n. B is the body forcing of the [potential part](#qtf-potential-part). HAMS's integral equation for a given normal derivative is the one of `ASSB_LEFT`, so φ_D = AMAT⁻¹ r with r_i = ∬_S G(x_i, ξ) b(ξ) dS_ξ, the same right side as `ASSB_RBC` forms for ∂φ/∂n = n_k with b in place of n_k. The load is

T_dir,k = iΩρ ∬_S (φ_I2 + φ_D) n_k dS.

For the same B and Q_D = 0, Green's theorem on φ_D and ψ_k (both harmonic in the fluid, with the same free-surface and radiation conditions at Ω) gives ∬_S φ_D n_k dS = ∬_S ψ_k ∂φ_D/∂n dS, so T_dir,k = T_pot,k of the potential part [derived by Green's second identity; the indirect form is Molin 1979]. Nemoh's `.12d` (direct) and `.11d` (indirect) are the same pair, and the design spec (`notes/specs/2026-11-04-second-order-waves-design.md`, Nemoh outputs) requires that they converge to each other. That is what the `.12d` against `.11d` check tests.

**B2 by the Stokes form with G.** B2 = −n·[(X·∇)u] has the same sharp-edge problem as in the potential part, so the Stokes form of [B2](#qtf-potential-part) is used with G(x_i, ·) in place of ψ. G(x_i, ·) is singular at x_i on S: ∇_ξ G goes like 1/ρ², with a leading part odd in the direction, so the surface term is a principal value and the identity keeps its form [derived, QTFDirect.f90 header]. One point per panel for the density on the 1/ρ² kernel converged only as h^0.65 at collocation points on S (0.186, 0.116, 0.075 at 128, 512 and 2048 panels on a sphere; the same rule gives O(h²) off the surface). So on the panels that `CALGREEN` takes as near (within 50 panel sizes) the Rankine part 1/r + 1/r₁ is integrated against a density linear on the panel, with closed-form first moments over flat panels (`rankine_moments`); the density gradient comes from `tangential_fit`. The wave part and the far panels keep the one-point rule. Panels that share a node with a panel across a sharp edge (normals more than `qtf_edge_angle` apart) keep the one-point rule, because u is singular there and the fitted gradient means nothing. The mask is built once per run (`direct_setup`).

The panel integrals of G and ∇_ξ G come from the stored arrays of the left side at Ω (`CGRN`, `RKBN`, `DS`, and the multi-body versions), so `CALGREEN` must have run at Ω before the right side is formed. They are single precision (`GRN_KIND = 4`); `green_panel_integrals` computes them afresh and is used by the tests.

**Solve.** At each Ω the matrix is the radiation matrix of `ASSB_LEFT` (LU factors with `ISOLV = 1`). With `ISOLV = 2` it is left unfactored for GMRES, and `direct_factor` factors it once per Ω (the direct solve is its last use at that Ω; a second factorisation would give a wrong φ_D with no error, so `direct_factor` records the Ω and stops on a repeat). The right sides of all pairs of one Ω are one block, `ZGETRS` with `NRHS` = the number of pairs, per symmetry block, in blocks of at most `DIRECT_BLOCK_BYTES` (256 MB) of work arrays. A pair with Ω < 0 is treated as `potential_pair` treats it: φ_D solves the problem at −|Ω|, whose matrix and Green function are the conjugates of those at |Ω|. The equal-frequency pairs (Ω = 0) need no solve: `.12d` equals `.10d` there, as `.11d` does.

**Irregular frequency removal (`If_remove_irr_freq = 1`).** The lid rows add r_l = ∬_S G(x_l, ξ) b dS at the lid points, with the stored lid integrals `DGRN` and `PKBN`, and the B2 part by the same Stokes form with G(x_l, ·), which is smooth since x_l is off the hull. The system is solved in the least-squares form of HAMS, (AᵀA) x = Aᵀ r with `CMAT`, and Aᵀ r formed as `ASSB_RBC_IRR` forms `DRMAT`. A mesh with no lid points stops the run (`check_lid`).

**Memory.** Besides the arrays of the potential part, `qtf_direct = 1` holds T_dir, `tdir(6·nbody, nfreq, nfreq, heading pairs)`, complex, 16 · 6 · nbody · nfreq² · (heading pairs) bytes, the size of T_pot. With `write_terms` 1 or 2 it also holds the arrays `tdir_i2` and `tdir_d`, of the same size each, for `QTF_DirectTerms.txt`. So the direct method adds 1 such array, or 3 with `write_terms`. The log line `QTF: with psi and the potential part the store takes ... MB` counts T_dir (it doubles the heading pairs, see `SecondOrderDriver.f90`) but not `tdir_i2` and `tdir_d`. For 101 frequencies, one body and one heading each array is 1.0 MB, so this matters only for many frequencies and heading pairs (for 1000 frequencies and 4 headings with `mean_drift = 2`, 16 pairs: 1.5 GB each [derived]). The work arrays of `direct_at_omega` are about 25 complex values per panel and pair (with the lid rows), in blocks of at most 256 MB.

### Free-surface forcing of the direct solve (Phase 7b)

With `qtf_terms = full` the right side of the direct solve gets the free-surface forcing of φ_D. Usage is in [QTFs, potential part](input_files.md#qtfs-potential-part), the columns in [Output Files](output_files.md#wamit-format), the numbers in [Second-order validation](second_order_validation.md#direct-method-with-the-free-surface-forcing).

**Formulation.** Q_D is the forcing of the free-surface condition of φ_D, −Ω²φ_D + g ∂φ_D/∂z = Q_D on z = 0, formed as in the indirect method by `fs_forcing_diff` (the total first-order fields minus the incident ones, KERNEL_DIFF), with g the gravity of the Green function, g = Ω²/V (`fs%g`). Green's second identity for φ_D and G over the fluid, bounded by the hull, the free surface F, the bottom and a far cylinder (n out of the fluid, ∇²G = −4πδ), gives at x on the hull −2πφ_D = ∬_S (φ_D G_n − G ∂φ_D/∂n) dS + ∬_F (φ_D G_z − G ∂φ_D/∂z) dS [derived, `QTFDirectFS.f90` header]. The bottom term vanishes (both have ∂/∂z = 0), and the far cylinder by the radiation condition. On F, G satisfies −Ω²G + g G_z = 0, so φ_D G_z − G ∂φ_D/∂z = −G Q_D/g. HAMS's equation 2πφ_D + ∬_S φ_D G_n dS = ∬_S G b dS therefore gets the term

r_FS(x) = (s_D/g) ∬_F G(x, ξ) Q_D(ξ) dS_ξ, with s_D = +1 (`DIRECT_FS_SIGN`).

The same r_FS is added at the lid points (0 in place of −2πφ_D, the same F term). The sign is pinned by `direct_fs_equals_indirect_full`: with s_D = +1 the difference to the indirect free-surface terms is 2.8e-3 of max |T_pot|, with −1 it is 0.78. The load of the free-surface part, T_FS,k = iΩρ ∬_S φ_D,FS n_k dS, equals FS_inner + FS_outer of the indirect method by Green's theorem (ψ_k and φ_D have the same conditions at Ω); the indirect term has the factor s_FS iΩρ/g with s_FS = +1 (`FS_SIGN`, QTFFreeSurface).

**Inner and outer split at R.** F is split as in the indirect method, at the circle R of `qtf_fs_radius`:

- *Inner* (the generated mesh or `FSInnerMesh.pnl`, nfs panels): r_in(x_i) = Σ_j gfs(i, j) w_j Q_D(ξ_j), with Q_D constant per panel (the one-point rule of `fs_inner_pair`) and gfs(i, j) = (1/w_j) ∬_panel j G(x_i, ξ) dS. A panel within 50 panel sizes of x_i takes the Rankine part 1/r + 1/r₁ in closed form (`rankine_moments`) and the rest G − 1/r − 1/r₁ by an n × n Gauss-Legendre rule on the panel, n = ⌈ln(1e8)/(2 ln ρ)⌉ with ρ = t + √(t²+1), t the distance over the panel radius, n from 1 to 8 (`fs_remainder_order`). One point (the rule of `CALGREEN`) was tried first and misses: 1.7e-3 of r_in on the 448-panel cylinder, since the rest is not smooth on the panel scale next to the waterline (a logarithm) and in finite depth (bottom images). The rule gives 6.5e-8 to 2.9e-7. A panel further away takes G at its centroid.
- *Outer* (annulus, tail and sliver beyond the inner mesh): there G(x_i, ·) on z = 0 is a sum of partial waves, so r_out(x_i) = Σ_mn a(m, n, i) mom(m, n), with the amplitudes of the row x_i and the moments of Q_D. The moments do not depend on the row.

**Graf partial waves of G.** `pw_green_modes` ([PartialWaves.f90](../src/PartialWaves.f90)) gives G(x, ·) for r_ξ > r_x as the eigenfunction sum of John (1950), as `FINGREEN3D` sums it (`EIGEN`): G = i P₀ H₀(k₀ρ) + Σ_n P_n K₀(k_n ρ), with the vertical eigenfunctions of the finite depth and ρ the horizontal distance. Graf's addition theorem (Abramowitz and Stegun 9.1.79, and 9.1.80 at ν = 0 with z → iz for K₀) gives H₀(k₀ρ) = Σ_m J_m(k₀ r_x) H_m(k₀ r_ξ) e^{im(θ_ξ − θ_x)} and K₀(k_n ρ) = Σ_m I_m(k_n r_x) K_m(k_n r_ξ) e^{im(θ_ξ − θ_x)}, all terms with sign +. So the amplitudes are a(m, 0) = i c₀ Z₀(z_x) J_m(k₀ r_x) e^{−imθ_x} and a(m, n) = c_n Z_n(z_x) I_m(k_n r_x) e^{−imθ_x}, with c₀ = 2πk₀/(k₀h sech²k₀h + tanh k₀h) and c_n = 4cos²k_n h/(h + sin 2k_n h/(2k_n)). I_m is computed as e^{−x} I_m(x) by Miller's backward recurrence (A&S 9.6.26, normalised by 9.6.34). The 1/r and 1/r₁ parts are in the series. Tests: the amplitudes against the direct eigenfunction sum to 6.6e-10, and against `FINGREEN3D` to 4.3e-7, which is its own accuracy there (the region uses `EIGENE` with `Limes`).

**Orders.** The m-th Graf term at r ≥ R is at most (r_x/R)^m/m (A&S 9.3.1), so M = `pw_green_mmax(r_max, R, 1e-8)`, r_max the largest horizontal distance of any row point from the centre. The n-th evanescent term is of order e^{−k_n(R − r_x)}, with k_n > (n − ½)π/h, which gives N_ev = ⌈L h/(πd) + ½⌉, L = ln(1/(1e-8 (1 − e^{−πd/h}))), d = R − r_max. N_ev grows like 1/d (a row at 0.9 R needs about 200). Both are capped where k_n R exceeds `PW_KR_MAX`, with a warning. `pw_green_modes` zeroes the orders whose H_{m+1}(k₀R) or K_{m+1}(k_n R) exceed 1e300 and returns the highest kept, `mcut`. Only |m| ≤ mcut is contracted, so there is never Inf × 0. If mcut < M, the dropped tail is at most q^(mcut+1)/((mcut+1)(1 − q)), q = r_max/R (`fs%cut_error`); above 1e-8 it is a warning, not a stop. The bound is large when R is close to the hull and the wave is long (3.4e-3 for R = 1.05 r_x at Ω = 0.01 rad/s in 15 m of water, from the review of the code); the cure is a larger `qtf_fs_radius`.

**Outer moments of Q_D.** `fs_outer_moments` ([QTFFreeSurface.f90](../src/QTFFreeSurface.f90)) gives mom(m, n) = ∬ B_mn Q_D dS over the annulus R to r_far, the propagating tail beyond it and the sliver between the polygon of the generated inner mesh and the circle, with B_m0 = H_m(k₀r)e^{imθ} and B_mn = K_m(k_n r)/K_m(k_n R) e^{imθ}. The amplitudes are in the form of the contraction of ψ (`set_amplitudes`): a(m, 0) as above and a(m, n) multiplied by K_m(k_n R), so that Σ a mom is the integral. The integral of e^{imθ} picks the coefficient q_m of e^{−imθ} of Q_D, so mom(m, n) pairs with a(m, n) at the same m. Tests: the contraction against the ψ path to 2.0e-15 and against G from `pw_green_modes` to 3.3e-15; and the strong form, with evanescent partial waves only, against a direct quadrature of G Q_D at three hull rows, 5.5e-8, 7.1e-7 and 2.2e-8 (`fs_rhs_outer_contraction`; pairing a(−m) with mom(m) gives 0.67). The one-pass moments cost 3.3 times the ψ integral of the same pair, since Q_D has to be expanded to |m| ≤ M instead of the mode count of ψ (`outer_moments_cost`). r_far is raised by `direct_fs_rfar` to R + 40/k₁ (k₁ the slowest evanescent wave number), where the dropped part is below e^{−40}.

**Normalisations and Ω < 0.** The moments carry no factor; r_FS = (s_D/g)[gfs (w q) + aᵀ mom] is two matrix products (`direct_fs_rhs`), added to the right side in the block layout of `ASSB_RHS_FIELD_IRR`, with the symmetry images by `RXY` (`RXY_MULTI`). The rows are all hull panels and, with `If_remove_irr_freq = 1`, all lid points. A pair with Ω < 0 has its right side at |Ω| from the conjugated forcing, and conj Q_D(1, 2) = Q_D(2, 1) (`pair_product` of KERNEL_DIFF), so the pair is evaluated as (2, 1), which is ordered as `fs_outer_moments` needs. The moments of (2, 1) are not conjugated: the B_mn belong to G at |Ω|. The solve is then that of 7a. With the 3-slice `parts` of `direct_at_omega` the free-surface right sides are their own block, which gives D_FS.

**Cost and memory.** Per Ω, `direct_fs_setup` builds gfs (rows × inner panels) and the amplitudes a((2M+1) × (N_ev+1) per row): 16 · rows · (nfs + (2M+1)(N_ev+1)) bytes, which the log gives. The near-panel rule costs up to 64 Green function calls per near pair, and nearly every pair is near, so the set-up is 1.3 s (448 rows), 6 s (1792) and 17 s (4032 rows, 360 inner panels, 809 MB) per Ω on 24 threads [measured on Snellius, validation page]. For 6000 rows, M = 57 and N_ev = 75 the amplitudes take about 0.8 GB and gfs about 0.5 GB [derived]. The orders and the size do not depend on Ω, so `body_terms_setup` logs them with `direct_fs_estimate` before the frequency loop and adds them to the memory estimate; N_ev grows like h/(R − r_max), and the allocations of `direct_fs_setup` stop with a message that names a larger `qtf_fs_radius`. Image rows could share base-row storage (a_mirror(m) = a(−m)); this is not done. Per pair the moments dominate (0.44 s on average on the Snellius sharp cylinder, 24 threads; 1.9 and 2.5 s for two pairs on 480 panels in 100 m of water, N_ev 129, 8 threads), the contraction takes 0.02 s. The pairs run one after another; only the radial annulus is parallel, with fixed blocks summed in order, so the bits do not depend on the thread count.

**Tests.** Unit tests: `test/test_partial_waves.f90` (`green_modes_match_fingreen`, `green_modes_near_circle`, `green_modes_match_decompose`, `green_modes_cut_reported`), `test/test_qtf_free_surface.f90` (`outer_moments_contract_psi`, `outer_moments_contract_green`, `outer_moments_cost`), `test/test_qtf_direct_fs.f90` (collected as `qtf_direct_fs`: `fs_green_matrix_matches`, `fs_green_near_waterline`, `fs_rhs_inner_only`, `fs_rhs_symmetry`, `fs_amplitudes_match_green`, `fs_rhs_order_cut_finite`, `fs_rhs_outer_contraction`, `fs_rfar_evanescent`, `direct_fs_equals_indirect_full`, `direct_fs_pair_order`, `fs_memory_estimate`) and `test/test_second_order_input.f90` (`qtf_direct_full_accepted`). ### Sum frequency of the direct method (Phase 7c-2)

`qtf = 2` or `3` with `qtf_direct = 1` and `qtf_terms = body` or `full` solves φ_D at the sum frequencies Ω = ω_i + ω_j and writes `QTF_Direct.12s` and `QTF_DirectTermsSum.txt`. Usage is in [QTFs, potential part](input_files.md#qtfs-potential-part), the files in [Output Files](output_files.md#wamit-format), the numbers in [Second-order validation](second_order_validation.md#direct-method-at-the-sum-frequency). The plan is `notes/plans/2026-11-15-phase7c2-direct-sum-frequency.md`; its rulings are cited as R1 to R7 below.

**Formulation.** At Ω⁺ = ω₁ + ω₂ > 0, φ_D solves the problem of the difference frequency with Ω⁺ for Ω: −Ω⁺²φ_D + g ∂φ_D/∂z = Q_S on z = 0, ∂φ_D/∂n = B − ∂φ_I2/∂n on S, the same radiation condition. Green's second identity for φ₂ (the part forced by B) and ψ_k at Ω⁺ gives ∬_S φ₂ n_k dS = ∬_S ψ_k (B − ∂φ_I2/∂n) dS. The integral over F vanishes, since the integrand is (Ω⁺²/g)(φ₂ψ_k − ψ_kφ₂) = 0, and the far-field integral vanishes since both are outgoing at k(Ω⁺). Nothing in the identity uses how Ω was formed: it needs Ω > 0, so that ψ at Ω is the outgoing potential [derived, header of `QTFPotential.f90`]. The difference needs ψ(−|Ω|) = conj ψ(|Ω|) for Ω⁻ < 0. The sum has Ω⁺ > 0 always, so it uses ψ as solved, with no conjugation and no Ω = 0 return. The same identity gives T_FS = s_FS (iΩρ/g) ∬ ψ_k Q_S dS and the sign s_D = +1 of the direct free-surface term, as at the difference frequency (pinned by `direct_fs_sum_equals_indirect`: the opposite sign is off by 1.5, the right one by 6.0e-3 of max |T⁺_pot|).

**The kernel switch.** `NearFieldDrift.f90` defines `KERNEL_DIFF = 1` and `KERNEL_SUM = 2` (`pair_minus` and `pair_plus`). The routines that depend on the pair kind take an optional `kernel` that defaults to `KERNEL_DIFF`, and with it the code is the difference code to the bit: `potential_pair`, `direct_at_omega` (one `kernels(npair)` entry per column), `pair_forcing`, `pair_densities`, `b2_stokes_densities`, `direct_fs_block`, and in `QTFFreeSurface.f90` `fs_pair_terms`, `fs_inner_pair`, `fs_outer_pair`, `fs_outer_tail`, `fs_outer_ring`, `fs_outer_sliver`, `fs_outer_rfar`, `fs_outer_moments`, `fs_forcing_points` and `fs_pair_order_message`. The bits are pinned by `pot_kernel_default`, `direct_kernels_default`, `fs_kernel_default` and `direct_fs_kernel_default`, whose stored values were printed from the code before the change. For a sum column:

- Ω = ω₁ + ω₂ and `dws(col)` is the signed Ω, here Ω⁺ > 0. The only conjugation in `direct_at_omega` is `IF (dws(col) < 0)`, which a sum column never meets, so its φ_D, its field-hook value and its B2 densities are those at Ω⁺, as solved.
- `incident2_pair` and every `pair_cross` (B1, B3, the B2 densities) take the kernel. B3 = −iΩ⁺ n·(H x) with H x = ½ α×(α×x): it is quadratic in α, so its sum-frequency part is ½ pair_plus(α, α×x) e^{−iΩ⁺t}, and d/dt gives −iΩ⁺. B1 keeps its form, since Ẋ = −iω_j X_j holds per component.
- The load factor is iΩ⁺ρ. A time-series reference tests the products (`pot_sum_b1_direct`, `pot_sum_b3_direct`): with ω₁ = 0.8 and ω₂ = 0.7 every frequency of the product of two two-component signals is a multiple of 0.1 rad/s, so over the beat period with 64 samples (1/N) Σ h(t_n) e^{iΩ⁺t_n} picks the part at Ω⁺ = 1.5 alone.

**Free-surface forcing at Ω⁺ (R3).** `fs_forcing` gives Q_D (`fs_forcing_diff`, the same code) or Q_S. T⁺ is symmetric (`pair_plus` = (f₁g₂ + f₂g₁)/4 in every term), so Q_S(1, 2) = Q_S(2, 1): the pairs are ordered ω₁ ≥ ω₂, the diagonal is a regular pair, and the swap in `fs_pair_terms` needs no conjugate. For the outer region the sum is the difference with ω₂ → −ω₂ and field 2 given unconjugated:

- the modes of field 2 and of I₂ are reversed, c₂(b) = X₂(−b), instead of conjugated, and `ring_coef` takes −ω₂ [derived term by term from `pair_plus` against `pair_minus`, `ring_coef` header; tests `fs_sum_ring_sampled` (2.2e-15 at 3 R) and `fs_sum_swap`];
- in the tail the propagating part of field 2 is H⁽¹⁾(k₂r) (Abramowitz and Stegun 9.2.3 and 9.2.4 for the asymptotic phases), so the phase classes of the three kinds of products are κ_a = k₁ + k₂ + K (S₁S₂ and both H⁽¹⁾ halves), κ_b = −k₁ + k₂ + K (the H⁽²⁾ half of I₁ with S₂) and κ_c = k₁ − k₂ + K (S₁ with the H⁽²⁾ half of I₂), with K = k(Ω⁺) [derived, `fs_outer_tail` header; test `fs_sum_tail_contour`, 5.9e-17 and 3.9e-16];
- all three classes are positive, since the dispersion relation is monotonic and so K > k₁ ≥ k₂, so none can vanish. The difference class −k₁ − k₂ + K tends to 0 in shallow water [derived, plan R3]. Test `fs_sum_classes_positive`: no class ≤ 0, the least 3.67e-2 1/m;
- `fs_outer_rfar` takes the least of the classes that occur (b only with incident wave 1, c only with wave 2), as for the difference. The evanescent part is not smaller for the sum: kev(1) falls as Ω rises (kev(1) h runs from π down to π/2), so with one evanescent mode the sum r_far − R is up to 1.065 times the difference one, and the test gates that ratio at 1.39 (1.3 × measured).

**The list of frequencies (R2, R6).** `qtf_omega_list(omegas_main, max_dw, sum_top, tol, want_diff, want_sum, need, reuse_index, is_diff, is_sum)` ([QTFDriver.f90](../src/QTFDriver.f90)) builds the union of the difference frequencies and, with `want_sum`, the sums ω_i + ω_j (i ≤ j) up to `sum_top`, merging values within tol/2. `is_diff(m)` and `is_sum(m)` say which kernels use `need(m)`; a frequency that is both (0.6 from 0.9 − 0.3 and 0.3 + 0.3) has one solve. ψ, ∇ψ on C and F and ψ on the inner free surface are kept at every entry. `qtf_radiation_list` is a wrapper with `want_sum = .FALSE.` and returns the old list to the bit (`omega_list_diff_unchanged`, three grids and two `qtf_max_dw`). `qtf_sum_limits` gives `sum_top`, the smaller of `qtf_max_sw` and the cutoff of the irregular frequencies (a hair below it, since a sum at the cutoff is left out). `sum_pair_index(i, j)` is the rule of the sum as `difference_pair_index` is that of the difference: 0 when ω_i + ω_j is beyond the cutoff, else its index in the list. `qtf_max_sw` is inclusive (to 1e-9) like `qtf_max_dw`; the estimate is exclusive (ruling T1-a). A sum-only Ω has no difference pair, so the difference direct solve skips it (`qtf_diff_omega`), but its radiation-only solve runs.

**The estimate of the irregular frequency (R2).** `irregular_frequency_estimate` takes the minimum over the closed waterline loops (`wl_next`) of √(g j₀₁ / a_eq), j₀₁ = 2.404826, a_eq = √(A/π), A the shoelace area of the loop. For a wall-sided hull the interior eigenfunction J_m(kr) sinh k(z + d) gives ω² = g k coth(k d) with coth ≥ 1, and by Faber–Krahn the disc of equal area has the lowest first Dirichlet eigenvalue (Pólya and Szegő 1951), so it is a lower bound [derived]. Tests: `irregular_estimate_cylinder` (1e-12 against the polygon, within 0.5% of 1.536 rad/s; the exact value of the sharp cylinder is 1.548) and `irregular_estimate_two_loops` (1.983 rad/s for a 6 m loop, the largest loop giving the minimum). For a hull that is not wall-sided it is not a bound: a row just above the true value can carry a spike, and the log says so. It is computed once, in `qtf_init`, with `If_remove_irr_freq = 0` only.

**One solve per Ω (Task 4).** `qtf_direct_at_omega` makes two `direct_at_omega` calls with one factorisation: first the difference pairs of Ω, exactly as without the sum (no `kernels`, the same parts slices and field points), then the sum pairs with `kernels = KERNEL_SUM` and `factored = .TRUE.` (a flag that skips `direct_factor`; with `ISOLV = 2` a second factorisation would stop the run). The reason is that MKL does not promise column p of `ZGETRS` and `ZGEMM` to be the same for another number of right sides, and the column blocks depend on it. With the two calls the difference columns are those of a `qtf = 1` run, so `qtf = 3` difference files equal the `qtf = 1` files (`qtf3_diff_unchanged`: tdir, tdir_i2 and tdir_d bit for bit, IRSP 0 and 1; and the integration test `direct_sum_qtf3_diff_unchanged`, whole files). The sum pairs of one Ω are the canonical half (R6: i < j, or i = j with b₁ ≤ b₂, `qtf_direct_sum_pairs`), and each result fills both slots of `tdir_sum` (`qtf_sum_store_symmetric`: equal to the bit).

**Stores and files.** `tdir_sum` and `tpot_sum` hold T⁺_dir and T⁺_pot, (6·nbody, nkept, nkept, heading pairs); with `write_terms` ≥ 1 `tdir_sum_i2`, `tdir_sum_d` and, with `full`, `tdir_sum_fs`. The difference stores (`tpot`, `tdir` and their parts) are allocated only with `qtf` 1 or 3. `potential_part_sum` computes T⁺_pot with `potential_pair(kernel=KERNEL_SUM)` and, with `full`, `fs_pair_terms(kernel=KERNEL_SUM)` from the same ψ (R1), always when the sum is on, as the cost estimate counts it. `qtf_finish` writes `.12s`: the rows of `.10s` with `sum_pair_index > 0`, each `.10s + tdir_sum`, the diagonal included. `qtf_stored_mb` adds 16 · 6 · nbody · nfreq² · nsum_pairs bytes. The field hook runs on the sum columns when `qtf_field = 1`: `qfield_keep_direct(..., kernel)` stores φ_D in a separate sum store (`dir_store_sum`), both slots, and `qfield_finish` writes it with Ω = ω_i + ω_j (`direct_field_sum_hook_matches`: bit equal; `field_direct_sum_rows`, `field_direct_sum_symmetric`, `field_direct_sum_cutoff`, `field_direct_sum_only`, `field_direct_both_kernels`). The field stays body-forced for both kernels (R4).

**The inner mesh and the stencil for the sum (R3 a to c).** The Green matrix and the amplitudes are built per Ω, so only the mesh and the mode counts follow the sum. `fs_setup(..., omega_sum_max)` calls `build_fs_inner` at max(ω_max, Ω⁺_max), so the generated inner mesh has the panel size λ(Ω⁺_max)/10 (16 times the panels in deep water); one mode count M = ⌈K(Ω⁺_max) R⌉ + 10 serves all partial-wave sets. The stencil offsets of φ_zz keep the first-order scale, `scale = max(psize, λ(ω_max)/10)` in `fs_inner_steps(..., scale)`, because the first-order fields vary on λ(ω) and a smaller offset raises the rounding error by 1/δ². The scale applies only when the generated mesh was refined for the sum (no `qtf_fs_panel`, no `FSInnerMesh.pnl`), so that `qtf = 3` difference files stay equal to `qtf = 1` (ruling T4-c). `fs_inner_steps_scale` checks it: 288 finer points, offset step × λ(1.1)/10, residual 1.1e-3 to 2.3e-3 against a gate of 3.1e-3 (1.3 × 2.32e-3; 6a measured 2.4e-3 at an offset of 0.2 m). The mesh matters: with an inner mesh built for 1.1 rad/s the sum at Ω⁺ = 1.40 differs from the indirect sum by 1.54e-2 of max |T⁺_pot| (100 points), with one built for 1.40 by 6.0e-3 (180 points) and for 2.0 by 4.5e-3 (648 points); the body-part gap is 2.6e-3 to 2.9e-3 (ruling T3-b).

#### The near-waterline fit of the inner fields

`fs_inner_fields` gives φ, ∇φ and φ_zz at the inner points from the panel solution, with ∇φ and φ_zz by a 5-point stencil whose offsets `fs_inner_steps` shrinks until the stencil clears the waterplanes by 16 offsets. Next to a waterline the offsets reach millimetres, below the scale on which the field of constant panels is smooth, and the differences amplify the panel-scale error: with exact panel data on the sharp m1 hull ∇φ is 3–105% and φ_zz 20–450% off within 1 m of the waterline, φ itself within 2.5% (`fs_fields_exact_inner`). At high Ω⁺ that strip carries a third of the free-surface term, which made the 7c-2 sum 8–24% off the exact one ([validation](second_order_validation.md#snellius-validation-task-8)).

`fs_waterline_fit_setup(mesh, geom, pts, step, fit, scale)` and `fs_waterline_fit_apply(mesh, fit, states, step, is_multi, f)` in [QTFFreeSurface.f90](../src/QTFFreeSurface.f90) replace those values (type `fs_wl_fit`, commit 47d5911):

- **Which points.** An inner point at distance s from the nearest waterline point p, with 0 < s < d0, d0 the length of that waterline segment (about one hull panel; ruling W1).
- **Samples.** `WLFIT_N` = 6 Gauss–Legendre points on the line from p through the point, at s/d0 in [1, 3]. They get their stencil offsets as the inner points do (`fs_inner_steps` with the same step and scale). A point whose samples come within d0 of a waterplane, or lie inside one, keeps the stencil and is counted in `fit%nskip` (W3).
- **The fit.** Per state (W2), the perturbation field at the samples (minus the exact incident wave) is fitted by least squares in σ = s/d0 and evaluated at the point; the exact incident wave is added back. The weights depend only on the geometry, so `fit%wt` is computed once and the driver calls the setup once. The basis is per quantity (`WLFIT_KINDS` = [0, 2, 2], W4): φ keeps the stencil (it is accurate there); the horizontal gradient and φ_zz use the cubic 1, σ, σ², σ³. ∂φ/∂z is not fitted: on z = 0 it follows from the free-surface condition of the panel solution, which the stencil does not difference.
- **Error floor.** The extrapolation gain of the weights is 2 at s = d0 and about 40 as s tends to 0 (cubic, six samples), so the stencil error of about 1% at the samples sets the 3.5–4.9% left next to the waterline.
- **Driver.** `SecondOrderDriver.f90` calls the setup after `fs_inner_steps` (both branches, with the sum scale when the mesh was refined for the sum) and the apply right after `fs_inner_fields`, for the difference and the sum alike. The log line names the points fitted, the samples and the points kept on the stencil.

The tests use the exact potential of the sharp cylinder on the hull panels, so no BEM solve: `fs_fields_exact_inner` (the fields on rings 0.1 to 3.5 m from the waterline, worst 4.9e-2 with the fit, 4.51 without), and `fs_fields_exact_integral` and `fs_fields_exact_integral_diff` (the inner integral over a < r < a + 5 m, 42.7% → 2.05% at the sum pair (1.4, 1.0) and 24.0% → 2.28% at the difference). The fixtures are written by `pre_postprocessing_python/SecondOrder/make_fs_fields_exact_fixture.py` (`--grid`, `--grid-diff`). The fit changes the difference free-surface terms too: the 7b fixtures `qtf_directfs_{round,irsp,two}` were re-pinned (largest change 4.9e-3 of the largest value) and the gate of `directfs_irsp_limit` went from 1.9e-3 to 2.5e-3.

### Indirect sum frequency without the direct solve (Phase 6b)

Phase 7c-2 computed T⁺_pot only with the direct solve; Phase 6b is wiring, with no new physics. **The sum switch.** `sum_on = opts%qtf >= 2 .AND. opts%qtf_terms >= QTF_TERMS_BODY` in `qtf_init` ([QTFDriver.f90](../src/QTFDriver.f90)); it had `qtf_direct = 1` as a third term in 7c-2. `body_terms` and `want_sum` in `SecondOrderDriver.f90` lost the same term, `uses_fs` is `qtf_terms = full` with `qtf` > 0, and `SecondOrderInput.f90` no longer stops `qtf = 2` with `qtf_direct = 0`. `diff_on` (`qtf` 1 or 3) and `sum_on` are independent, so `body_active` covers `qtf = 2` alone.

**The frequency list.** `qtf_omega_list` gets `want_diff = diff_on` and `want_sum = sum_on` (`qtf_init`), so with `qtf = 2` the list holds the sum frequencies only (`is_sum`, no `is_diff`). `qtf_radiation_omegas` returns the entries not on the main grid (`PACK(psi_need, psi_reuse == 0)`), and `RadiationOnlySolves` in `HAMS_Prog.f90` solves each once without the direct solve (`qtf_direct = 0` takes this branch; `qtf_direct = 1` takes `qtf_direct_omegas`, which includes the main grid). The radiation-only solve at a sum frequency is the same as at a difference one, so ψ at Ω is the same in both routes. `psi_need` is the union list (differences, then sums, merged within the tolerance) and `psi_reuse(m)` the main-grid index of entry m, or 0. It computes each pair of `sum_pair_index` > 0 by `potential_pair(kernel=KERNEL_SUM)` and with `full` `fs_pair_terms(kernel=KERNEL_SUM)`, fills both slots (i, j) and (j, i), and with `pot_sum_terms` writes the terms of both rows through `write_pot_rows`. `tpot_sum` is allocated `IF (body_active .AND. sum_on)`; `tdir_sum` only with the direct solve. `qtf_indirect_sum_load` gives a stored pair to the tests.

**Files.** `write_file(…, KERNEL_SUM)` in `qtf_finish` opens `QTF_Indirect.11s` when `sum_on` and writes, for each row of `.10s` with `sum_pair_index > 0`, `total + tpot_sum`, the diagonal included; with `qtf_direct = 1` `.12s` is written beside it. `write_potential_sum_terms_header` ([SecondOrderOutput.f90](../src/SecondOrderOutput.f90)) writes the four comment lines of `QTF_PotentialTermsSum.txt`: 15 columns with `body`, 19 with `full` (`write_qtf_terms_row`, 16 digits). `psi_bad_files` and `bad_files` in `potential_part_sum` name `.11s` and its terms file in the messages of a non-finite ψ or pair, so the count of `qtf_nonfinite_pairs` now includes `.11s`.

### Second-order motion (Phase 6c)

`qtf_motion = 1` solves the second-order motion ξ⁽²⁾ of the free bodies at every row of `.11d` and `.11s`, and with `qtf_direct = 1` of `.12d` and `.12s`, and writes `QTF_Motion.11d`, `.11s`, `.12d` and `.12s`. With `qtf_field = 1` and `qtf_direct = 1` it also adds the radiated wave of that motion to `QTF_Field.txt`. Usage is in [Second-order motion](input_files.md#second-order-motion), the files in [Output Files](output_files.md#wamit-format), the numbers in [Second-order validation](second_order_validation.md#second-order-motion). The plan is `notes/plans/2026-11-17-phase6c-second-order-motion.md`; its rulings are cited as R1 to R8 below.

**The equation and its convention.** The motion is ξ(t) = Re(ξ e^{−iΩt}), the convention of the second-order force T before the output conjugation. The velocity of mode k is −iΩ ξ_k, so the radiation potential is ψ_k (−iΩ ξ_k), with ψ_k the unit-velocity radiation potential at Ω (∂ψ_k/∂n = n_k, n out of the fluid). The linear pressure −ρ ∂φ/∂t then has the amplitude ρΩ² ξ_k ψ_k, and the force on the body is F_l = Ω² ξ_k ρ ∫ ψ_k n_l dS = (Ω² A_lk + iΩ B_lk) ξ_k, with ρ ∫ ψ_k n_l dS = A_lk + i B_lk/Ω as in `RFORCE` ([PotentWavForce.f90](../src/PotentWavForce.f90)). This is F = −A ξ̈ − B ξ̇ (Newman 1977, ch. 6). Newton's law with the hydrostatic restoring C, the external spring K_ext and the linear damper B_ext gives

[−Ω²(M + A(Ω)) − iΩ(B(Ω) + B_ext) + C + K_ext] ξ⁽²⁾ = F⁽²⁾.   (1)

`SolveMotion` ([SolveMotion.f90](../src/SolveMotion.f90)) works in e^{+iωt}: it solves LEFT · DSPL = −i conj(EXFC) with LEFT = −ω²(MATX + AMAS) + iω(BDMP + BLNR) + CRS + KSTF. The conjugate of LEFT is the matrix of (1) at Ω = ω, so (1) with F = i EXFC gives ξ = conj(DSPL). The unit test `motion_first_order_limit` runs `SolveMotion` in the same process on the round body at 0.7 rad/s, with springs and a linear damper set, and pins this to 4.2e-16 relative; with the sign of the damping term flipped it fails with 4.3e-1. The files are conjugated on output, as `.10d` (R4).

**A and B from ψ (R2).** `radiation_coefficients(mesh, psi, omega, rho, a, b)` ([QTFMotion.f90](../src/QTFMotion.f90)) forms a(l, k) = ρ Re S_lk and b(l, k) = ρΩ Im S_lk, with S_lk = Σ ψ(i, k) n_l(i) area(i) over the panels of the body of mode l. It works on the expanded mesh, whose `nj` already carry the image signs, so no RX, RY factor is needed. It takes ψ from `psi_store`, which the potential part fills at every Ω of the list, so the motion needs no extra radiation solve. It is a new routine on explicit arrays, not a call of `RFORCE`, which writes into the per-frequency arrays and prints files. At main-grid frequencies it equals `RFORCE` to 7.9e-16, `RFORCE_MULTI` for two bodies to 8.9e-16, and on a half mesh 1.1e-15 (unit tests `radiation_coefficients_*`, [validation](second_order_validation.md#second-order-motion)).

**The solve per Ω (R6).** `motion_matrix(omega, mass, a, b, b_ext, c, k_ext, lhs)` returns the matrix of (1). `motion_solve_omega(lhs, forces, xi, ok, rcond)` factors a copy of it with `ZGETRF` after `ZLANGE` gives its 1-norm, estimates the reciprocal condition number with `ZGECON` (LAPACK Users' Guide, 3rd ed., Anderson et al. 1999, section 4.4), and solves every force column of that Ω with one `ZGETRS`. If `ZGETRF` finds an exactly zero pivot, rcond is set to 0. `ok = rcond >= 1e-12`; when not ok, ξ = 0 and the driver leaves the pairs of that Ω out of the files. The matrix is not equilibrated: on the moored cylinder of the tests rcond is 2.3e-2 to 8.7e-2, and the singular cases (free surge, sway and yaw) have rcond exactly 0, so equilibration would not change which Ω are flagged (Task 4 of the plan, measured). One `ZGETRS` on all columns differs from one call per column by 2.3e-15 relative (MKL takes other kernels for one right side; unit test `motion_columns_independent`).

**Signs of Ω.** A difference row (i, j) with ω_i < ω_j has Ω < 0. A and B are even in Ω, since the radiation force of a real motion has conjugate coefficients at ±Ω; with M, C, K_ext and B_ext real the matrix at −|Ω| is then conj(lhs) of the one at |Ω|. `qtf_motion_part` solves lhs conj(ξ) = conj(F) with the factors of |Ω| and conjugates the result, so each Ω has one factorisation for both signs. **Ω = 0** (the difference diagonal) is static: `motion_matrix` at Ω = 0 with A = B = 0 is C + K_ext. For a singular Ω, `free_modes` names the modes whose row or column is zero to 1e-12 of the largest entry (surge, sway and yaw of an unmoored body); `omega_left_text` writes them into the log line and the file header.

**Damping (R5).** The matrix has B(Ω) + `BLNR`. `BQDR` is linearised on |ξ⁽¹⁾| and iterated in `SolveMotion`; it has no second-order form and is not used. `body_terms_setup` ([SecondOrderDriver.f90](../src/SecondOrderDriver.f90)) logs one warning when any entry of `BQDR` or `BQDR_MULTI` is not zero.

**The driver.** One module with adapters (D7): `QTFMotion` uses only `SecondOrderTypes` and works on explicit arrays, for any number of bodies; the adapters are in `QTFDriver` and `SecondOrderDriver`.
- `body_terms_setup` assembles M = `MATX`, C = `CRS`, K_ext = `KSTF` and B_ext = `BLNR` (one body) or the `block_diagonal` of their `_MULTI` forms, and passes them to `qtf_init` as the optional `mass`, `c_hyd`, `k_ext` and `b_ext`, each (6N, 6N) with N bodies. It adds `nmotion` to the store estimate (`qtf_stored_mb`).
- `qtf_init` allocates `xi2(6N, nfreq, nfreq, heading pairs, routes)` with the difference and `xi2_sum` with the sum, route 1 the indirect force and route 2 the direct one (`qtf_direct = 1`), and per Ω of the list `mot_ok`, `mot_rcond`, `mot_free` and `mot_solved`, indexed 0 to `nneed` (0 is Ω = 0). For a fixed body `mot_active` is false, nothing is allocated, and the log notes it once.
- `qtf_finish` calls `qtf_motion_part` after `potential_part`, the direct solves and `potential_part_sum`, and before the writers. Per Ω with rows it calls `radiation_coefficients`, `motion_matrix` and, per kernel and route, one `motion_solve_omega` over the pairs of that Ω, and it logs Ω with its rcond. `pair_force` gives the force of a row with the same sums as `write_file`, so the force is that of the file to the bit.
- `write_file` writes `QTF_Motion.*` beside its force file, with `open_motion_file` for the header and `write_motion_row` ([SecondOrderOutput.f90](../src/SecondOrderOutput.f90)) for the rows: conj(ξ) L for a translation and conj(ξ) L² for a rotation.
- `qtf_motion_load` returns ξ, the force and `ok` of a row for the tests.

**The radiated wave in the field (R7).** Only the direct route has a second-order potential at the field points, so the radiated wave goes into `QTF_Field.txt` only with `qtf_direct = 1`. φ_R = Σ_j (−iΩ ξ_j) ψ_j enters as φ_D does: p = iρΩ φ_R and η = (iΩ/g) φ_R.
- `psi_at_points` ([QTFDriver.f90](../src/QTFDriver.f90)) evaluates ψ_j at the points by Green's formula with the body values of ψ_j and ∂ψ_j/∂n = n_j: `direct_field_at_points` ([QTFDirectField.f90](../src/QTFDirectField.f90)) on the 6N ψ columns. It sits in `QTFDriver`, not `QTFField`, because `QTFField` cannot use `QTFDirect` (`QTFDirect` uses `QTFFreeSurface`, which uses `QTFField`).
- `qtf_direct_at_omega` stores ψ at the points per Ω in `mot_psi_pts` (`keep_psi_points`), after the direct solves.
- `motion_field_part`, called by `qtf_finish` after `qtf_motion_part`, forms φ_R with ξ of route 2 for each row with a direct part whose Ω has `mot_ok`, through `radiated_potential` ([QTFField.f90](../src/QTFField.f90)), and adds it to the stored φ_D with `qfield_add_radiated`, which marks the row in `rad_have` (`has_rad`).
- For Ω < 0, `radiated_potential` takes conj(ψ): the unit-velocity potential at −|Ω| is conj(ψ(|Ω|)). The row (i, j) is then the conjugate of its mirror, as for φ_D.
- `write_field_row` ([SecondOrderOutput.f90](../src/SecondOrderOutput.f90)) writes the column `has_rad` only when its optional `has_radiated` is given, which `qfield_finish` does only with the radiated wave on (`qfield_radiated_active`). So `qtf_motion = 0` gives the 7c-2 file, to the byte (`field_radiated_off`).
- ψ at the points costs one more field pass of 6N columns per Ω, about twice a plain Green row pass, because `direct_field_at_points` always runs the B2 integrals, here with zero densities. `mot_psi_pts` (16 · (points) · 6N · `nneed` bytes) is not in `qtf_stored_mb`.

**Python.** `truncated_cylinder_reference.py qtf-motion` solves (1) for surge, heave and pitch of the sharp cylinder from the exact T, A and B, with the springs and dampers of the validation case, and `qtf_compare.py --motion` compares the files with it ([Python Scripts](python_scripts.md)). The reference keeps the M and C of the exact circle; the HAMS m1 polygon has M and C about 0.6% lower.

### Partial second-order field (QTFField.f90)

`QTFField.f90` writes `QTF_FieldPartial.txt` (`qtf_field = 1`): the second-order pressure and elevation at the field points of `ControlFile.in`, from the quadratic part and the second-order incident potential of `SecondOrderIncident.f90` only. The second-order diffracted potential and, for a free body, the potential radiated by its second-order motion are omitted. Near the bodies, where the free-surface forcing drives the second-order scattered wave, the omitted part is not small ([Partial second-order field](input_files.md#partial-second-order-field-at-the-field-points)). The complete field is a later phase.

`field_pair` uses Bernoulli's equation expanded about z = 0 (Dean and Dalrymple 1991), time factor $e^{-i\omega t}$: $p^{(2)} = -\rho[\phi^{(2)}_t + \frac{1}{2}|\nabla\phi^{(1)}|^2]$ at a fixed point below z = 0, and $\eta^{(2)} = -\frac{1}{g}[\phi^{(2)}_t + \frac{1}{2}|\nabla\phi^{(1)}|^2 + \eta^{(1)}\phi^{(1)}_{zt}]$ on z = 0, with $\eta^{(1)} = (i\omega/g)\phi^{(1)}$ and $\phi^{(1)}_{zt} = -i\omega\,\phi^{(1)}_z$. For the ordered pair (i, j) of unit waves and the kernel P of `NearFieldDrift` (`pair_minus` for the difference, `pair_plus` for the sum), with $u_m$ the components of $\nabla\phi^{(1)}$:
- quad_p = −(ρ/2) Σ_m P(u_im, u_im, u_jm, u_jm);
- quad_η = −(1/g) [½ Σ_m P(u_im, u_im, u_jm, u_jm) + P(η_i, −iω_i u_i3, η_j, −iω_j u_j3)];
- pot_p = iρΩ φ₂(x), pot_η = (iΩ/g) φ₂(x), with Ω = ω_i − ω_j (difference) or ω_i + ω_j (sum) and φ₂ the second-order incident potential of the pair (`incident2_phi`), made with the same kernel.

These are T⁻_ij and T⁺_ij in the sense of `QTF_Quadratic.10d` and `.10s`: the physical $e^{-i\Omega t}$ amplitude is, for i ≠ j, 2 a_i a_j* (quad + pot) for the difference and 2 a_i a_j (quad + pot) for the sum; for i = j it is a_i² (quad + pot) for the sum and |a_i|² (quad + pot) for the mean. For the sum kernel, `incident2_pair` (optional argument `kernel`, default the difference) takes Ω = ω_1 + ω_2, K = k_1 e_1 + k_2 e_2 and the free-surface forcing with `pair_plus`, with no diagonal short-cut. The incident potential takes the gravity of `wave_gravity`, as the QTFs do; Bernoulli takes `G` of `Const_mod`, the one of the first-order elevation. The pressure and the elevation are conjugated and scaled only in `write_field_row` (`SecondOrderOutput.f90`).

`build_field_points` turns the points into a `cs_points` set of kind `CS_FREE`, so that `fields_green` (`FieldVelocity.f90`) computes φ at every point. Its rules: |z| ≤ 1e-6 is an elevation point (z set to 0), z < −1e-6 a pressure point, z > 1e-6 rejected; a point within `psize(i)` of a hull centroid i is on the hull; a point is inside body b when the winding number of body b (`body_winding`) is more than 0.5. It sums the solid angles (Van Oosterom and Strackee 1983, IEEE Trans. Biomed. Eng. 30(2), 125–126) of the triangles of the hull panels, symmetry images included, and of their mirror in z = 0, each turned to face out of the body; the hull and its mirror form a closed surface for a surface-piercing body, and the mirror of a submerged body lies above z = 0. An earlier rule, the side of the nearest centroid's panel plane, stopped valid points below the hull near an edge where fine wall panels meet a coarse bottom (unit test `points_mixed_panel_sizes`). The points are checked in order, and the first that fails gives the message. `psize` and `body` of a point are those of the nearest hull panel; the finite-difference step is `FIELD_FD_STEP` = 0.02 of that size.

At the end of each frequency of the QTF grid, `field_frequency` (`SecondOrderDriver.f90`) calls `fields_green` for all headings and `qfield_keep` stores φ and ∇φ: 4 complex values per point, frequency and heading. `fields_green` builds one influence row per stencil point and applies it to every heading: 7 rows for a point below z = −δ (the centre and ±δ along x, y, z), 5 for a point from z = −δ up (the centre and ±δ along x, y, with ∂φ_P/∂z = ν φ_P). After the frequency loop, `qfield_finish` forms the pairs in the loops of `qtf_finish` (kernel, β1, β2, i, j, then the point), with `qtf_max_dw` on the difference pairs, so that the pairs are those of `.10d` and `.10s`. Its state is module state, as for `QTFDriver.f90`.

## Continous Integration in GitHub Actions

The project has [Continuous Integration (CI)](https://www.software.ac.uk/guide/how-continuous-integration-can-help-you-regularly-test-and-release-your-software) workflows in place to verify the program compiles and runs correctly. The workflows are configured with [GitHub Actions](https://docs.github.com/en/actions). They automatically compile HAMS-MREL and run the tests.

There are two workflows: one for Windows and another for Linux. Both run independently of each other and results can be seen in the [Actions tab](https://github.com/vaibhavraghavan/HAMS-MREL-DCC/actions) of the GitHub repository. The workflows are automatically triggered whenever a new commit is pushed to the repository (main or develop branch) or a pull request is opened. Running the workflows when a pull request is opened helps us verify that the changes that will be integrated compile correctly and don't cause tests to fail.

Both workflows define a single job each: *Build and Test*. The job:
- Configures the GitHub runner (server) where the workflow is executed. This means installing the Intel compilers and Intel OneAPI Math Kernel Library, Fortran Package Manager and Test-Drive framework.
- Compiles HAMS-MREL
- Runs the tests

To simplify the installation of the dependencies mentioned above, we use Actions from the [GitHub Actions marketplace](https://github.com/marketplace?type=actions). Actions can be thought of as mini-apps, extensions or plugins that do one thing specifically. In this case, the Actions install different software on the GitHub Actions runners. The following Actions are used:
- [setup-fortran](https://github.com/marketplace/actions/setup-fortran): install the Fortran Intel compiler and Intel OneAPI Math Kernel Library (Linux only)
  Although the setup-fortran action can install the Intel Fortran compiler on both Windows and Linux, installation of the oneMKL library is only available for Linux systems. Intel dependencies are manually installed on the Windows runner.
- [setup-fpm](https://github.com/marketplace/actions/setup-fpm): install the Fortran Package Manager

**The Windows workflow configuration is defined in [build_and_test_windows.yml](../.github/build_and_test_windows.yml).**

**The configuration for Linux is in [build_and_test_linux.yml](../.github/build_and_test_linux.yml).**

## Iterative Solvers

HAMS-MREL supports two linear-solver paths for the BEM system, dispatched at runtime by the `ISOLV` parameter in `ControlFile.in` (1 = direct LU, default; 2 = GMRES). The full user-facing description is in [iterative_solvers.md](iterative_solvers.md); this section covers the developer-side layout.

**Source files:**

| File | Contents |
|---|---|
| [`src/IterativeSolvers.f90`](../src/IterativeSolvers.f90) | Restarted GMRES(m), block-diagonal LU preconditioner, Block GMRES with deflated initial guesses. Public entry points: `ZGMRES_SOLVE`, `ZBLOCK_GMRES_SOLVE`, `ZITER_SOLVE_MULTI`, `SETUP_BLOCK_PRECONDITIONER`. Uses inline BLAS (`ZDOTC`/`DZNRM2`/`ZGEMV` unrolled) to sidestep known ifort/MKL calling-convention issues with the compiled BLAS bindings. |
| [`src/HMatrix.f90`](../src/HMatrix.f90) | Hierarchical-matrix compression: cluster tree, block cluster tree with admissibility test, Adaptive Cross Approximation (ACA), fast H-matvec. Public entry points: `HMATRIX_BUILD`, `HMATVEC`, `HMATRIX_DESTROY`. |

**Dispatch pattern:**

Each of the four `AssbMatx*.f90` files gates the LAPACK path on `ISOLV`. `ASSB_LEFT*` skips the `ZGETRF` factorization when `ISOLV > 1`. Each `RADIATION_SOLVER*` / `DIFFRACTION_SOLVER*` branches: `ISOLV = 1` uses the existing in-place `ZGETRS` path (Phase 2.4 — passes `AMAT`/`CMAT` directly, no full-size workspace copy); `ISOLV = 2` allocates a scratch matrix, builds the H-matrix + block preconditioner, and calls `ZITER_SOLVE_MULTI`.

**Interaction with `GRN_KIND=4`:**

The `ACA_TOL` and `ITER_TOL` constants are both `1e-4`, matched to the ~`1e-7` per-entry precision floor of an `AMAT` assembled from single-precision Green's-function values. Iterative results agree with the direct-LU reference at 4–5 significant figures on physically meaningful entries. For bit-identity against WAMIT references, users should stay on the default (`GRN_KIND = 8`, `ISOLV = 1`).

**Adding a new iterative test:**

Small multi-body test cases with `ISOLV = 2` can be added to `test/integration_tester.f90`. The recommended check is that `ISOLV = 2` output agrees with an `ISOLV = 1` baseline to `1e-3` relative on the WAMIT `.1` (`AmssDamp.1`) file peak-magnitude entries.

## Profiling Results

This section documents the primary sources of memory consumption in HAMS-MREL and how they scale with problem size. It is intended to guide future development and optimization efforts aimed at reducing RAM usage.

Profiling of HAMS-MREL shows that memory usage is dominated by a small number of large, multi-dimensional arrays whose sizes scale with the number of bodies and the number of panels per body. These arrays are dynamically allocated before the main solver iteration loop begins and remain allocated for the duration of the simulation.

### Observations

- **Dominant memory consumers**
  - The first two dimensions of these arrays scale linearly with the total number of panels across all bodies, resulting in a quadratic growth in memory usage as the number of bodies increases.
  - The variables are allocated once per program execution, before the solver iteration begins.
- **Overall memory behavior**
  - For a given simulation, memory usage is largely constant throughout execution.
  - Peak memory consumption is approximately 2 GB for the cases studied.
  - Memory does not accumulate across solver iterations.
