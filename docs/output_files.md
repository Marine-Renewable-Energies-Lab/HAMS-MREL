# Output Files

HAMS-MREL produces output files in multiple established formats (HAMS-specific, WAMIT and Hydrostar) to support post-processing and compatibility with external tools. All formats—and all files within each format—are produced automatically whenever the solver runs. Users cannot enable, disable, or selectively suppress the creation of specific formats or individual output files.

The type and number of files depends on the number of bodies: HAMS and WAMIT files are generated for both single and multi-body simulations, while Hydrostar output is produced only for single-body cases.

All output files are written to the output directory. Users may specify this directory when launching the program. Otherwise, HAMS-MREL creates a default `Output` folder next to the executable.

The sections below describes the content and structure of each file format in detail. Every listed output file includes a reference to the exact subroutine and source file responsible for writing it.

## Error Check

The `ErrorCheck.txt` file provides a summary of key system parameters and body information to help verify that the simulation setup is correct. It allows users to quickly confirm that simulation parameters have been set correctly before running the solver. The file is always generated by HAMS-MREL, regardless of the number of bodies. The file is written by the subroutine [CreateErrorCheckFile](https://github.com/vaibhavraghavan/HAMS-MREL/blob/26c0e7bac25c42d1f7eba1b0ce375b50ca33d00e/src/InputFiles.f90#L322), in [InputFiles.f90](../src/InputFiles.f90).

Contents:
- Water depth
- Frequency settings (if defined by the user)
    - Starting frequency
    - Spacing between frequencies
- Rotation center, per body
- Center of gravity, per body

All quantities except the center of gravity are defined by the user in `ControlFile.in`. For single-body simulations, the coordinates are written once. For multi-body simulations, coordinates for each body are listed sequentially.


## HAMS Format

HAMS-MREL generates output files in its native HAMS format for both single and multi-body simulations. The files contain added-mass, radiation-damping, and excitation-force data, respectively. For each quantity, six files are generated, one for each of the six degrees of freedom:

| File | Quantity | Columns | Rows | Writer Subroutines |
| :--- | :--- | :--- | :--- | :--- |
| `OAMASS<1-6>.txt` | added-mass | 8 - frequency, wave number and added mass for the six degrees of freedom | $num$ $frequencies$ $*$ $(num$ $bodies)^2$ | `RFORCE` and `RFORCE_MULTI` |
| `ODAMPING<1-6>.txt` | damping coefficients | 8 - frequency, wave number and damping for the six degrees of freedom | $num$ $frequencies$ $*$ $(num$ $bodies)^2$ | `RFORCE` and `RFORCE_MULTI` |
| `OEXFOR<1-6>.txt` | excitation forces | 4 - frequency, wave number and real and imaginary parts of the excitation force | $num$ $bodies$ $*$ $num$ $headings$ $*$ $num$ $frequencies$  | `EFORCE` and `EFORCE_MULTI` |

In all files, the output frequency type is defined by the user in `ControlFile.in` via the `OUFT` parameter.

All writer subroutines are located in [PotentWavForce.f90](../src/PotentWavForce.f90) and  [PotentWavForceMulti.f90](../src/PotentWavForceMulti.f90).


## WAMIT Format

The WAMIT format files provide results in a structure compatible with the [WAMIT software](https://www.wamit.com). Results in this format can be easily visualized with [BEMRosetta](https://github.com/BEMRosetta/BEMRosetta) and [BEMIO](https://wec-sim.github.io/bemio/). The files include frequency and direction-dependent quantities such as added mass and damping matrices, excitation forces, body motions, pressures, and hydrostatics. Each file is always generated by HAMS-MREL, regardless of the number of bodies.

**Reference Manual:** For detailed conventions, definitions, and file formats, see the [WAMIT 7.x Manual](https://www.wamit.com/manual7.x/v75_manual.pdf).

WAMIT files:
- `AmssDamp.1 file`: the frequency‑dependent **added‑mass $A_{ij}$ and damping coefficients $B_{ij}$** matrices for the radiation problem, over a range of wave frequencies (periods). The file contains 5 columns: period, i, j, $A_{ij}$, $B_{ij}$. The number of rows for a single-body siumulation is: $6 x 6$ $x$ $num$  $periods$. For multiple bodies, the number of rows is $n$ - $bodies$  $x$ $6 x 6$ $x$ $num$  $periods$.

    - *See Wamit Manual section 5.2*
    - Written by the subroutine `RFORCE` ([PotentWavForce.f90](../src/PotentWavForce.f90)) for single-body simulations and `RFORCE_MULTI` ([PotentWavForceMulti.f90](../src/PotentWavForceMulti.f90)) for multiple-body simulations.
 
- `ExcForce.3 file`: the frequency and direction dependent wave **excitation force vector $X_{i}$** from the diffraction problem. The elements of the vector are defined in terms of their magnitude (Mod), phase in degrees (Pha), and also in terms of their real (Re) and imaginary (Im) components. The file contains 6 columns: period, wave heading, i, $Mod(X_{i})$, $Pha(X_{i})$, $Re(X_{i})$, $Im(X_{i})$. The number of rows for a single-body simulation is: $6$ $x$ $num$ $headings$ $x$ $num$ $periods$. For multiple bodies, the number of rows is $n$ - $bodies$  $x$ $6$ $x$ $num$ $headings$ $x$ $num$  $periods$.

    - *See Wamit Manual section 5.2 and 3.3.*
    - Written by the subroutine `EFORCE` ([PotentWavForce.f90](../src/PotentWavForce.f90)) for single-body simulations and `EFORCE_MULTI` ([PotentWavForceMulti.f90](../src/PotentWavForceMulti.f90)) for multiple-body simulations.

- `Motion.4 file`: the **motion amplitudes vector $\epsilon_{i}$**. The elements of the vector are defined in terms of their magnitude (Mod), phase in degrees (Pha), and also in terms of their real (Re) and imaginary (Im) components. The file contains 6 columns: period, wave heading, i, $Mod(\epsilon_{i})$, $Pha(\epsilon_{i})$, $Re(\epsilon_{i})$, $Im(\epsilon_{i})$. The number of rows for a single-body simulation is: $6$ $x$ $num$ $headings$ $x$ $num$ $periods$. For multiple bodies, the number of rows is $n$ - $bodies$  $x$ $6$ $x$ $num$ $headings$ $x$ $num$  $periods$.

    - *See Wamit Manual section 5.2 and 3.4.*
    - Written by the subroutine `SolveMotion` ([SolveMotion.f90](../src/SolveMotion.f90)) for both single and multi-body simulations.

- `PressureElevation.6p file`: the hydrodynamic **pressure/free surface elevation on the body** for the radiation $p_i$ and diffraction problems $p_D$. The file contains two types of outputs:
    - period, $i$, $Re(p_1)$, $Im(p_1)$, $Re(p_2)$, $Im(p_2)$ $...$ - This will be 12 columns (real and imaginary part for 6 DOFs) for the radiation pressure/elevation values per body per field point. The number of rows would be $num$  $periods$ $x$ $num$ $fieldpoint$ $x$ $n$ - $bodies$.
    - period, wave heading, $i$, $Re(p_D)$, $Im(p_D)$ - This will be 2 columns for the real and imaginary part of the diffraction pressure/free surface elevation per field point. The number of rows would be $num$  $periods$ $x$ $num$ $fieldpoint$.

    - *See Wamit Manual section 5.2 and 3.5.*

    - If `separate_wamit_diffraction_and_radiation_files` in ControlFile.in is set to 1, the outputs are split into: `PressureElevationRadiation_<n-body>.6p` (one file per body) and `PressureElevationDiffraction.6p`. 

    - Single-body simulations are written in subroutines `OutputPressureElevation_Radiation` and `OutputPressureElevation_Diffraction` ([PressureElevation.f90](../src/PressureElevation.f90))
    - Multi-body simulations are written in subroutines `OutputPressureElevation_RadiationMulti` and `OutputPressureElevation_DiffractionMulti` ([PressureElevationMulti.f90](../src/PressureElevationMulti.f90))

- `PressureElevationIncidence.6p file`: written for multi-body simulation only in subroutine `OutputPressureElevation_IncidenceMulti` ([PressureElevationMulti.f90](../src/PressureElevationMulti.f90)). 

- `Hydrostat.hst file`: the non-dimensional **hydrostatic matrix $C_{ij}$**. The file contains three columns: i, j, $C_{ij}$. The number of rows is 36 for a single-body simulation (combinations of i and j). For multiple bodies, the number of rows is $n$ - $bodies$  $x$ $36$.

    - *See Wamit Manual section 5.6.*
    - Written by the subroutine `ReadHydroStatic` ([HydroStatic.f90](../src/HydroStatic.f90)) for single-body simulations and `ReadHydroStaticMulti` ([HydroStaticMulti.f90](../src/HydroStaticMulti.f90)) for multi-body simulations.

- `MeanDriftMomentum.8 file`: the **far-field mean drift loads**, written only when `SecondOrder.in` switches on `mean_drift` and `drift_methods` includes `far`. The file contains 8 columns: first-order frequency column, $\beta_1$, $\beta_2$, I, Mod, Pha, Re, Im. I = 1, 2, 6 are the force in x, the force in y and the moment about the global z axis through the origin, of the whole system. Forces are divided by $\rho g L$ and moments by $\rho g L^2$, with $L$ the reference length `REFL`, so the values are per unit wave amplitude pair. Pha is in degrees.

    - The first column is `OUFR`, in the form chosen by `Output_frequency_type` in `ControlFile.in`. WAMIT always writes the period here.
    - With `mean_drift = 1` there are 3 rows per frequency and heading, with $\beta_1 = \beta_2$. With `mean_drift = 2` there are 3 rows per frequency and pair of headings. The mean load of two waves of amplitudes $A_1$, $A_2$ at the same frequency is then $|A_1|^2 F_{11} + |A_2|^2 F_{22} + 2 Re(A_1 A_2^* F_{12})$, and $F_{21} = F_{12}^*$. Values follow the time factor $e^{+i\omega t}$ of the other WAMIT-format files.
    - The zero and infinite frequencies added by `0_inf_frequency_limits = 1` have no rows.
    - Written by the subroutine `write_drift_row` ([SecondOrderOutput.f90](../src/SecondOrderOutput.f90)).
- `MeanDriftPressure.9 file`: the **near-field mean drift loads, per body**, from pressure integration over the mean wetted surface, written only when `drift_methods` includes `near`. The columns, the scaling and the time factor are those of `MeanDriftMomentum.8`. The index is $6(b-1)+I$, for body $b$ and $I = 1, \ldots, 6$: the force in x, y, z and the moment about x, y, z, in global axes. Moments are about `XR` of that body, so they are not directly comparable with I = 6 of `MeanDriftMomentum.8`, which is about the origin. There are 6 rows per body, for each frequency and heading or pair of headings.
    - With `velocity_method = differencing`, near-field converges slowly on hulls with sharp edges, such as a flat bottom meeting a wall. `velocity_method = source` takes away most of that excess on one cylinder, measured at 448 and 1792 panels and 3 frequencies, with no other sharp hull tried. The exception is the free cylinder at 0.70 rad/s, where the error goes from 11.05% to 13.70% as the mesh refines. It is less close than differencing on rounded hulls. Rows cosine spaced towards the waterline converge: on a free rounded cylinder on springs, near-field is 1.36%, 0.40%, 0.21% above far-field at 480, 1920, 4320 panels, at 1.10 rad/s. On such hulls the far-field method is the reference for $F_x$, $F_y$ and $M_z$ of the whole system. When both methods run, the log prints their relative difference per frequency and heading for those three loads, with $M_z$ moved to the origin. The difference has no meaning for a load that is zero by symmetry, so the values are printed with it. See [the test fixtures](../test/data/drift_cyl/README.md) for values against panel count.
    - The log also gives the number of panel values whose velocity had only its normal part, for lack of neighbours. With `velocity_method = source` it gives the time of the source solve instead.
- `MeanDriftControlSurface.7 file`: the **control-surface (middle-field) mean drift loads, per body**, written only when `drift_methods` includes `control`. They come from the total first-order field on a closed surface C around each body and on the line $\Gamma_c$ where C meets the free surface, by Chen (2007) eq. (39) to (41); WAMIT v7.5 eq. 15.58 and 15.59 have the same terms. The columns, the scaling and the time factor are those of `MeanDriftMomentum.8`, and the index is $6(b-1)+I$ as in `MeanDriftPressure.9`, with the moments about `XR` of that body. I = 1, 2, 6 (the force in x and y and the moment about z) are always written. I = 3, 4, 5 (the vertical force and the moments about x and y) also take the free surface F between the hull waterline and $\Gamma_c$, the hull waterline and the second-order hydrostatic load, by Chen (2007) eq. (37) and (38). They are written for a body whose C has a bottom, when F could be built. When C reaches the sea bed they are not written, and the log says `control surface of body <b> reaches the sea bed: F_z, M_x, M_y not computed.`; the sea bed between the body and C would be one more boundary. So there are 6 or 3 rows per body, for each frequency and heading or pair of headings. The zero and infinite frequencies added by `0_inf_frequency_limits = 1` have no rows.
    - For I = 3, 4, 5, every `control` run also builds F and evaluates the field on it, and computes the hull velocity and the waterline potential (by `velocity_method` and `waterline_method`, as for `near`), even without `near`. There is no switch to leave them out. So a `control` run without `near` also logs the velocity fallback count (or the source solve time), and with `waterline_method = field` it also stops on the flare check and prints the finite-depth warning of `near`. Accuracy, measured on a rounded-bilge and a sharp-bilge cylinder (a = 10 m, 100 m depth, defaults of `cs_*`, `cs_velocity = green`): M_x and M_y are within max(1% of near-field at 7680 or 7168 panels, 0.001 rho g A^2 a^2) at 4320 and 7680 panels (4032 and 7168 on the sharp hull). The rounded-hull F_z at 4320 panels is within 1% of the extrapolated near-field limit, except about 2% (fixed) at 1.10 rad/s. On the 480-panel test hulls these loads are within 16% (free) and 29% (fixed) of near-field, which is itself not converged there; use a finer mesh. On a hull with sharp edges, F_z of the control-surface method is the better value: from 4032 to 7168 panels it changes by 0.8% or less, where near-field changes by 3% to 22%. On the fixed hull it is within 1% of the extrapolated near-field limit; on the free hull within 1% to 5%, and at 0.70 rad/s inside the range of the extrapolation. Near-field F_z at 7168 panels is still 13% to 19% off on the fixed hull and 24% to 68% off on the free hull (against the control-surface value), with the wrong sign at 0.70 rad/s. At 1.6 to 1.8 rad/s, F_z, M_x and M_y differ from near-field of the same mesh by up to about 30% at 1920 (rounded) and 1792 (sharp) panels; these frequencies were not run on finer meshes. Details: `test/data/drift_cyl/README.md`.
    - C of body b is written to `CSMesh_{b}.pnl` in the output directory, in the `HullMesh.pnl` format, so that it can be checked or read back with `cs_shape = file`.
    - The log gives the number of panels on C and F and of segments on $\Gamma_c$, and the time spent on the fields on C at each frequency. When `far` also runs, it prints the relative difference from far-field per frequency and heading for $F_x$, $F_y$ and $M_z$, with $M_z$ moved to the origin, as for near-field.
    - Written by the subroutine `write_drift_row` ([SecondOrderOutput.f90](../src/SecondOrderOutput.f90)).
- `MeanDriftTerms.txt file`: the terms of the near-field and control-surface loads, written when `drift_methods` includes `near` or `control` and `write_terms` is 1 or 2, after comment lines starting with `#`: one, one for `near`, and one for `control` (two when F is built, the second for terms 14 to 16). The control line says I = 1 to 6 even when rows 3 to 5 are not written. The columns are the first-order frequency column, $\beta_1$, $\beta_2$, body, I, term, Re, Im, with I = 1, ..., 6 as in `MeanDriftPressure.9`, and the same scaling and time factor. Each near-field load is the sum of its terms: 1 waterline, 2 flare (vertical force and its moment only), 3 velocity, 4 displacement, 5 rotation, 6 hydrostatic. Terms 1 and 2 are exactly zero for a body with no waterline. Each control-surface load is the sum of its terms: 11 the line integral on $\Gamma_c$, 12 the momentum flux through C, 13 the pressure term on C, and for I = 3, 4, 5 also 14 the hull waterline term, 15 the free-surface term on F, 16 the hydrostatic term.
    - Written by the subroutine `write_terms_row` ([SecondOrderOutput.f90](../src/SecondOrderOutput.f90)).

## Second-Order Diagnostics

`SecondOrder/PanelDiagnostics.txt` is test and debugging output, written only with `write_terms = 2` in `SecondOrder.in`. All its values are per unit wave amplitude, in SI units, with time factor $e^{-i\omega t}$ and angles in degrees. Each row starts with a tag:

| Tag | Columns | Content |
| :--- | :--- | :--- |
| `WAVE` | $\omega$, $k$, $\nu$, $h$ | Once per frequency. $h < 0$ is deep water. |
| `MODE` | $\omega$, $j$, $\theta$, Re $a_j$, Im $a_j$ | Far-field amplitude of the wave radiated by unit motion in mode $j$, at 72 angles, once per frequency. |
| `RESIDUAL` | $\omega$, $\beta$, $r$ | $r = \lvert[-\omega^2(M+A) - i\omega B + C]\xi - F\rvert / \lvert F\rvert$. It is meaningful only without quadratic damping, and absent with `motion_state = fixed`. |
| `FORCE` | $\omega$, $\beta$, $j$, Re $F_j$, Im $F_j$ | Excitation force, recovered as $F = i \cdot$ `EXFC`. |
| `TOTAL` | $\omega$, $\beta$, $\theta$, Re $a$, Im $a$ | Far-field amplitude of the perturbation wave, at the same 72 angles. |
| `PANEL` | $\omega$, $\beta$, panel, x, y, z, Re $\phi_D$, Im $\phi_D$, Re $\phi$, Im $\phi$ | Potentials at the panel centroid: diffraction, $\phi_D = \phi_I + i \cdot$ `MXPOT`, and total, including the motions. Symmetry images follow the base panels. |
| `SOURCE` | $\omega$, $\beta$, panel, then each as Re, Im: $\phi_P$, $\phi_\sigma$, $\partial\phi_P/\partial n$, $\nabla\phi_P \cdot n$, $\nabla\phi_P$ (3 components) | Only with `velocity_method = source`. The perturbation potential of the direct solve and of the sources, the normal derivative, and the velocity from the sources. |

Written by [SecondOrderDriver.f90](../src/SecondOrderDriver.f90).

## Hydrostar Format

The Hydrostar format output is provided for compatibility with the [Hydrostar software](https://marine-offshore.bureauveritas.com/hydrostar-software-powerful-hydrodynamic). Currently, these files are only generated for single-body simulations. Documentation for this format will be added in the future.
